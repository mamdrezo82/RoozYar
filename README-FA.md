# روزیار — نسخه وب آنلاین (آماده‌سازی Supabase)

این بسته نسخه وب روزیار را با اتصال اختیاری به Supabase آماده می‌کند: ورود گوگل، ذخیره آنلاین اطلاعات هر حساب و پشتیبان‌گیری/بازیابی فایل JSON. برای آنلاین شدن واقعی باید تنظیمات حساب‌های Supabase، Google OAuth و میزبانی را خودت انجام بدهی؛ این بسته هنوز به اینترنت منتشر نشده است.

## ۱) تنظیم Supabase

1. در Supabase پروژه را باز کن.
2. از بخش Project URL و API Keys مقدار Project URL و کلید **Publishable** را بردار.
3. فایل `supabase-config.js` را باز کن و `YOUR_SUPABASE_URL` و `YOUR_SUPABASE_PUBLISHABLE_KEY` را با آن دو مقدار جایگزین کن.
4. **هرگز** `SUPABASE_SECRET_KEY` یا `service_role` را داخل فایل‌های وب نگذار و برای کسی نفرست.
5. در داشبورد Supabase > SQL Editor فایل `supabase-setup.sql` را اجرا کن. این جدول `roozyar_user_data` و سیاست‌های RLS را ایجاد می‌کند تا هر کاربر فقط ردیف خودش را بخواند و تغییر دهد.

## ۲) فعال کردن ورود با گوگل

1. در Supabase به Authentication > Providers برو و Google را فعال کن.
2. در Google Cloud Console یک OAuth Client از نوع Web application بساز.
3. آدرس Callback URL ارائه‌شده توسط Supabase را در Authorized redirect URIs گوگل وارد کن.
4. Client ID و Client Secret را فقط در تنظیمات Provider گوگل داخل Supabase وارد کن؛ آن‌ها را در `app.js` یا `supabase-config.js` قرار نده.
5. بعد از انتشار سایت، دامنه نهایی را در Supabase Authentication > URL Configuration به عنوان Site URL و در Redirect URLs اضافه کن. برای آزمایش محلی، `http://localhost:8080/**` را هم به Redirect URLs اضافه کن.

## ۳) اجرای محلی برای آزمایش

- با Python نصب‌شده، از داخل همین پوشه اجرا کن: `py -m http.server 8080`
- سپس در مرورگر باز کن: `http://localhost:8080`
- ورود گوگل و Supabase به اینترنت نیاز دارد. برای آزمایش OAuth، آدرس localhost را در Redirect URLs مجاز کرده باش.

## ۴) انتشار رایگان روی Cloudflare Pages

- از داشبورد Cloudflare Pages یک پروژه Direct Upload بساز و محتوای همین پوشه را منتشر کن. فایل `index.html` باید در ریشه خروجی باشد.
- پس از گرفتن دامنه `*.pages.dev`، آن را در تنظیمات URL های Supabase و تنظیمات OAuth اضافه کن.
- اگر پس از انتشار مقادیر `supabase-config.js` را تغییر دادی، نسخه جدید را دوباره منتشر کن.

## ذخیره‌سازی و حریم خصوصی

- داده‌های هر حساب در یک ردیف با `user_id` مربوط به همان کاربر ذخیره می‌شود و RLS این مالکیت را enforce می‌کند.
- `localStorage` فقط حافظه محلی/کش دستگاه است؛ اطلاعات اصلی برای حساب متصل از Supabase خوانده می‌شود. اگر برای یک حساب داده‌ای وجود نداشته باشد، برنامه می‌پرسد آیا داده محلی همین دستگاه را به آن حساب منتقل کند؛ فقط در صورت اطمینان از مالکیت داده تأیید کن.
- فایل پشتیبان JSON از امکانات موجود برنامه استفاده می‌کند. فایل پشتیبان را در محل امن نگه دار؛ شامل اطلاعات شخصی خودت است.
- پلن رایگان سرویس‌ها محدودیت مصرف دارد و رایگان بودن دائمی/بدون محدودیت تضمین‌شده نیست.

## نکته مهم

این بسته کدهای اتصال و تنظیمات لازم را فراهم می‌کند، اما تا زمانی که کلید عمومی، SQL، Google OAuth و انتشار را انجام ندهی، ورود و همگام‌سازی آنلاین فعال نخواهد شد. هیچ کلید محرمانه‌ای نباید داخل فرانت‌اند قرار بگیرد.
